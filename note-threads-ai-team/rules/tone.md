# トーンと構成のルール（Threadsの絵文字のみ未確定）

## 1. 基本トーン：等身大の実録
| 項目 | ルール |
|---|---|
| 立ち位置 | 「ゼロから挑戦中の本人」。専門家・成功者として振る舞わない |
| 一人称 | 私（変更可） |
| 文体 | **note：です・ます調（2026-11-10確定）**。気持ちの声や見出し・強調の短い一文に限り、常体（「〜したい。」「〜だろう。」）を混ぜてよい／Threads：短文、です・ます調を基本に口語を少し混ぜてよい |
| 失敗の扱い | 各記事に最低1つ、実際の失敗・未解決の課題を入れる |
| 言葉 | 内部の呼び方（「記事チーム」など）を説明なしで使わない。AIの役割は「28人」ではなく「28の役割」と書く（人数のように読める誇張を避ける） |
| 数字 | 実測値のみ。「いつ時点の」「何日間で」を必ず添える。予測は「目標」「見込み」と明記。**自分の目標金額は記事に書かない**（account_profile.md「当面の公開方針」） |
| 絵文字 | note：使わない。使う場合も1記事に合計1〜2個まで。**リンク誘導の矢印（⬇️など）や見出しの目印も個数に含める**（2026-11-10承認）。誘導は「▼」「→」などの記号か文字で行う／Threads：暫定1投稿1個まで。よく見られている投稿の絵文字の個数を調べて決める（未確認） |

## 2. noteの実録記事の構成型（参考記事の分析から抽出）
0. **目的**（2026-11-10追加）：1行目で「何のためにやっているのか」を書く。本人の動機は本人の言葉を使う（account_profile.md「発信の目的」）。手段（AIの使い方）だけで始めない
1. **冒頭**：今の結果と数字（良くも悪くも）を先に示す
2. **きっかけ・経緯**：日別、またはフェーズ別のタイムライン
3. **仕組みの全体像**：役割の図や表
4. **工夫したポイント**：3〜5個
5. **失敗・罠**：何が起きて、どう直したか
6. **実績データ表**：指標と数値（実測のみ）
7. **読者が真似できる最小ステップ**：3〜5ステップ
8. **まだできていないこと**：未解決の課題を正直に書く
9. **まとめ・CTA**：次の記事、リスト登録、有料部分への案内

- 文字数の目安（推測）：無料記事は3,000〜6,000字。参考記事は約2,500字と約11,500字（記号・空白を除いた概算）で、幅が大きい。運用しながら数値データで見直す。

## 3. Threads投稿の型
- 1行目に主張か意外性を書く（「Threadsマネタイズ完全攻略ガイド」P56、P72の論点を参考）
- 続けて、理由・具体例・補足を書く
- 実録の数字を入れる場合は、時点を明記する

### 読み取れること（推測、確信度：低）
- 4記事とも、です・ます調が中心。常体は、心の声（「どうしよう…」「始められない…」）、太字の問いかけ（「なぜこんなに差が生まれてしまうのか？」）、まとめの箱の中の短文に限って使われている。
- 絵文字は本文で0〜4個。多くは⬇️（リンクへの誘導）や🍀（見出しの目印）といった「機能的な絵文字」で、感情を表す絵文字（😭）は1記事に1個程度。
- 3〜4記事とも見出し画像がある。Aは図解、B・Dは自分の管理画面やスプレッドシートの数値画像を載せている（実録の「実績データ表」と同じ考え方）。
- Dは自分の12記事の数値（合計ビュー1,526、合計スキ396）をジャンル別に集計し、仮説を立てている。表の値から計算すると、note初心者ジャンルのスキ率は254÷672＝37.8%で記事内の数値と一致（Pythonで確認）。
- Dは外部データの出典（調査名・URL）を明記している。一方で「元記事は削除済みでn数は不明」と自ら書いており、根拠としては弱い。Bは「一般的に3%〜10%程度」という平均を出典なしで示している。当チームでは、出典のない数値や確認できない出典の数値は載せない（rules/ng_expressions.md No.3、事実確認担当で確認）。

### 限界
- 5記事のうち3記事が同じ書き手（ねこ）で、書き手の癖に偏っている。ランキングから選んだものではない。
- 運用開始後は、自分の記事の読了率やスキ率で見直す。

### 特典の設計（3回目の共有で追加、2026-11-10）
記事Eの購入者特典：①設計シート（ワークシート）②公式LINE招待（購入者限定で情報共有）③DMでの質問対応 ④本人が運営している実物の公開 ⑤Zoomでの作戦会議（8/9追記、「商材販売はありません」と明記）⑥追加の作り方解説（10/9追記）。受け取り方法は有料部分の下部に記載。

| 特典の型 | 当チームでの扱い | 理由 |
|---|---|---|
| ワークシート・テンプレート | **採用（第一候補）** | 一度作れば手間が増えない。このAIチームの設計ファイル（役割定義、チェックリスト）自体が特典になる |
| 購入者限定のLINE招待 | **2か月目から採用** | 購入者をリストに変える導線になる（rules/account_profile.md のリスト計画と一致） |
| 日付つきの追記（特典の追加） | **採用** | 記事を育て続けられる。追記した日付を必ず書く |
| DM質問対応・Zoom面談 | **当面は採用しない** | 平日2時間の作業時間では、購入者が増えるほど対応できなくなる。対応する場合は件数・期限・範囲を明記する |
| 実物の公開 | 実物がある場合のみ | 実録の証拠になる |

- 特典の告知でも、Zoom面談などで別の商品を売る場合はその旨を明記する（記事Eは「商材販売はありません」と明記している）。
- 購入者に付ける特典が、景品表示法の「景品類」にあたるか、商品の内容の一部とみなされるかは、個別の判断が必要（確信度：中）。特典は「有料部分の内容の一部」として記事内に明記し、判断がつかない場合は承認1で確認する。
- 記事Eは箇条書きの目印に絵文字（✅、🚫）を使っているが、当チームは使わない（tone.md 1章：目印も個数に含める）。
