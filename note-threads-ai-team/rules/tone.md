# トーンと構成のルール（Threadsの絵文字のみ未確定）

## 1. 基本トーン：等身大の実録
| 項目 | ルール |
|---|---|
| 立ち位置 | 「ゼロから挑戦中の本人」。専門家・成功者として振る舞わない |
| 一人称 | 私（変更可） |
| 文体 | **note：です・ます調（2026-11-10確定）**。気持ちの声や見出し・強調の短い一文に限り、常体（「〜したい。」「〜だろう。」）を混ぜてよい／Threads：短文、です・ます調を基本に口語を少し混ぜてよい |
| 失敗の扱い | 各記事に最低1つ、実際の失敗・未解決の課題を入れる |
| 数字 | 実測値のみ。「いつ時点の」「何日間で」を必ず添える。予測は「目標」「見込み」と明記 |
| 絵文字 | note本文：使わない、使う場合も1記事に1〜2個まで（2026-11-10承認）／Threads：暫定1投稿1個まで。現在よく見られている投稿の絵文字の個数を調べて決める（未確認） |

## 2. noteの実録記事の構成型（参考記事の分析から抽出）
1. **冒頭**：今の結果と数字（良くも悪くも）を先に示す
2. **きっかけ・経緯**：日別、またはフェーズ別のタイムライン
3. **仕組みの全体像**：役割の図や表
4. **工夫したポイント**：3〜5個
5. **失敗・罠**：何が起きて、どう直したか
6. **実績データ表**：指標と数値（実測のみ）
7. **読者が真似できる最小ステップ**：3〜5ステップ
8. **まだできていないこと**：未解決の課題を正直に書く
9. **まとめ・CTA**：次の記事、リスト登録、有料部分への案内

- 文字数の目安（推測）：無料記事は3,000〜6,000字。参考記事は約2,500字と約11,500字（記号・空白を除いた概算）で、幅が大きい。運用しながら数値データで見直す。

## 3. Threads投稿の型
- 1行目に主張か意外性を書く（「Threadsマネタイズ完全攻略ガイド」P56、P72の論点を参考）
- 続けて、理由・具体例・補足を書く
- 実録の数字を入れる場合は、時点を明記する

### 読み取れること（推測、確信度：低）
- 3記事とも、です・ます調が中心。常体は、気持ちの声（「難しい…」）や太字の一文（「柔軟にしていきたい。」）に限って使われている。
- 絵文字は、本文では0〜2個。見出しの目印として同じ絵文字をそろえて使う例がある（A）。
- 3記事とも見出し画像があり、Aは本文中に図解、Bは管理画面の数値の画像を載せている（実録の「実績データ表」と同じ考え方）。
- Bは「一般的に3%〜10%程度」という平均を出典なしで示し、末尾で「公式平均ではない」と断っている。当チームでは、出典のない平均値は載せない（rules/ng_expressions.md No.3）。

### 限界
- 3記事・画面に写った範囲のみで、件数が少ない。「よく見られている記事」の代表とは言えない（ランキングから選んだものではない）。
- 運用開始後は、自分の記事の読了率やスキ率で見直す。
